# 小猫 0.2.1 正式运行切换

本版从功能日报候选 `52175b4` 继续修正发布时发现的两类问题：本地模型的引用可能使用省略文字，单个失效工作树会阻断同仓其余工作树的清单构建。

模型改为选择程序生成的差异单元和原文引用编号。编号由程序还原成不可变的单元、方向和原文，继续通过原有来源、前后方向、变更种类、版本及状态校验。完整的小差异可独立解读，不再被同文件其他超限函数连带拒绝。输入超出预算时选取有界片段，未解读单元仍保留在规则结果和详细依据。模型每项目最多生成五条核心说明。模型输出使用独立的中文解释字段，避免复制输入代码；行为调整使用 behavior/reliability 类型，修复结论仍受旧行为证据约束。未分配功能的遗留工作在正文按项目汇总，完整条目继续保留在依据中。

工作树清单逐项核验。一个失效的 Git 目录只记录该路径的采集缺口，后续正常树继续核验。已确认属于登记仓库的开发树从未知候选中移除。第三方 Token Monitor 安装目录继续排除。

## 正式入口

- 固定程序目录：`~/Library/Application Support/Xiaomao/release/v0.2.1`，独立 `.venv`，两个任务及 SwiftBar 使用同一份固定源码。
- 扫描：每 300 秒，规则采集，不进行业务仓测试。
- 日报：Asia/Taipei 每日 21:30；另每 300 秒检查错过的已截止窗口。生成模型解读时释放采集锁及写事务。
- 菜单：每分钟读取同一日报窗口及证据版本；完整正文和详细依据分别打开。
- 观察：原六个登记项目及确认属于个人账号的目录；《旷野之心》原目录与同仓副本纳入同一项目；各项目启用全部经核验的开发工作树。未知归属仍为候选。

初次启用只建立基线。启用前没有采集到的未提交内容不算作启用后的新增成果。首日晚间报告须明确说明只从切换时刻开始获得新版证据。先前报告与观察记录保留；旧报告的覆盖范围不会改写为新版范围。

## 发布与恢复

先在隔离开发树和环境中运行回归及验收。切换前备份配置、两个 plist、菜单链接、报告和一致性的 SQLite 快照。新版数据库增量迁移到 schema 4，逐项核对旧记录保留。

确认后台任务空闲后卸载旧入口，建立基线并固定新源码，更新入口、重新加载任务，核对一次真实扫描、日报、原文引用、菜单版本以及提醒去重记录。外盘身份及现有本地模型另作运行检查。测试集里的模型、通知和进程控制仍使用替身。

恢复必须同时还原旧程序入口、旧配置和对应数据库快照；恢复前另存新版数据库与报告。不要删历史记录或失效工作树来掩盖采集缺口。

发布证据与可执行恢复脚本存放在正式 home 的 `backups/runtime-20261005-*` 中。隔离验收通过、运行检查通过、连续三个真实开发日对账是三个不同阶段；前两项通过不能代替后续真实工作对账。

## 后台目录权限

定时任务直接运行的 Python 不继承 Codex 已有的磁盘权限。若后台在读取文稿内工作树的 Git 指针时阻塞，先停止小猫任务并恢复旧运行状态，再由用户决定授予后台程序所需目录权限或调整观察范围。不要把手动运行成功当作 launchd 成功，也不要自动扩大系统隐私权限。
