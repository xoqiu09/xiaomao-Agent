# 功能日报

## 输出契约

每个项目优先回答「功能做了什么变化、影响哪段使用流程、代码推进到哪一步」。正文最多展示 5 项；数量不足不补写。其余功能条目、完整提交、作者、工作树与原文支持在 `reports/daily-evidence/日期.txt`，可从 SwiftBar 的「查看日报依据」或 `latest daily --details --print` 查看。

一条功能记录包含功能名称、类型、修改前后说明、影响、实现进展、交付状态、来源及解释方式。实现进展与交付状态分开：已提交不能证明任务完成、测试通过、已合并或正式启用。Git 作者由程序展示，本机操作者未知。每条模型说明标为静态解读，不能替代运行证据。

同功能的代码与文档、多个文件或提交可归为一条；一次提交里的不同功能可拆开。功能目录匹配优先使用符号，其次路径。没有可靠目录时，模型可从有界上下文提出功能名；它作为本次报告解读保存，不自动成为已确认的目录规则。没有可用解读则写「功能影响待确认」，技术证据仍保留。优先级来自确认的功能目录及变化类型，文件数量不提高优先级。

## 项目背景与修正

扫描读取获准项目的有界 README，提取含代码路径的功能表/标题映射；复用已经消化、来源哈希仍匹配的 briefing 缓存。不会枚举公司说明目录，不在采集时调用模型。每个背景保存来源类型、内容版本和用途；说明中的计划只作为背景。

```bash
xiaomao features show --project PROJECT_ID
xiaomao features set --project PROJECT_ID --file catalog.json
```

目录文件例子：

```json
{
  "purpose": "汇总本机个人项目每天的功能进展",
  "features": [
    {
      "id": "daily-summary",
      "name": "每日工作总结",
      "paths": ["src/app/daily*.py"],
      "symbols": ["build_daily"],
      "priority": 3
    },
    {
      "id": "recovery",
      "name": "任务恢复",
      "paths": ["src/app/recovery.py"],
      "priority": 2
    }
  ]
}
```

优先级 3 为核心行为，2 为普通功能，1 为维护。每项目最多 40 项，每项最多 30 个路径和符号。路径是项目内的匹配规则，不扩大采集权限；可使用通配符。修正只保存到小猫数据库，追加版本，从后续采集生效。既有观察和旧日报继续使用当时版本；不会改写业务仓库。

## 时间和证据

- 提交上下文来自该提交及其父版本；工作区上下文在扫描时保存。日报不会用今天的源码推断昨天的功能。
- 完整源码先脱敏，再提取变化行及附近声明/调用片段。小文件快照用于计算两次观察之间的增量；大型文件、预算不足或旧版证据无法形成可靠增量时，明确降级。
- 昨日遗留且今日未变只列进行中。观察到整组或部分文件恢复时，尝试与恢复合并呈现。连续提交链回到相同内容可说明已恢复；缺少链路时不猜测撤销。
- 同仓同 SHA 只统计一次。不同工作树保留不同内容时分开说明；工作树来源保存在详细依据。
- 输入预算沿用每项目最多 `min(48000, context_length * 2)` 字符。差异与代码上下文共享原 64 KiB 字符预算；新目录数据有单独有界限制。超限、暂停、模型不可用或调用失败均保留规则报告。

## 模型校验与降级

每个有变化的项目分别调用已有本地模型，采集锁和事务已释放。缓存键包含模型、提示版本、范围、窗口证据及背景版本。查询和菜单刷新只读。

模型输出按功能给出记录，每条必须引用本窗口的代码单元，并提供改动前/后相应方向的原文支持。校验拒绝不存在的来源、过时版本、纯文档冒充实现、格式整理冒充新增能力，以及无依据的完成、合并、部署、测试或性能结论。作者、提交和进行中状态由程序计算。单条失败不会丢掉其他有效解读，遗漏的单元保留待确认记录。

这些检查可以确认引用、来源类别与方向，不能以程序形式证明每句自然语言都理解正确。实际模型的理解质量需要另用真实项目样例审阅；隔离测试使用替身，只验证采集、归并、校验、展示和降级链路。

## 隔离样例和验收

```bash
.venv/bin/python -m tests.feature_scenario --output /tmp/xiaomao-feature-example
.venv/bin/python scripts/accept.py --isolated
```

样例在临时目录创建 3 个仓库、5 棵工作树：同一日报提交跨副本去重，另一项目保留草稿实现，第三项目只有昨日遗留修改。断言事先标注的功能句、提交状态、窗口、项目与模型调用覆盖；文件名不能进入正文，必须可从独立依据读取。所有模型和提醒均使用替身，不控制真实进程。

发布仍是独立步骤：候选 PR 不合并，不切正式 release、plist、launchd 或 SwiftBar。正式启用后连续 3 个真实开发日对账，并审阅真实本地模型的功能解释。
