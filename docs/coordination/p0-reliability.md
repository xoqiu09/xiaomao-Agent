# 小猫 P0 可靠性开发任务

> 2026-10-26：本文原为云端仓库 `xiaomao-agent-cloud` 准备，该仓库已停用。P0 改在本机从 `main` 切分支开发，任务内容不变。

## 目标与本轮边界

让小猫在数据库忙、单棵工作树读取失败或代码证据不完整时，仍能给出准确、可恢复的结果。失败不能被写成正常成功，只读查询不能为初始化数据库而争抢写锁，也不能读取旧成功资料掩盖本次失败。

交付代码、实际复现、回归检查和 Draft PR；合并、正式安装和用户验收由用户另行决定。旧设计还包含 P1 到 P3，这些阶段不属于本轮。

本轮基线是 `main`（含文档交接模块 `documents.py` / `document_mcp.py`，修改锁与 store 时不得破坏它们）。生产程序尚未实施本轮 P0 修复。不要把历史锁定现象当成已定位根因，先检查调用链。

## 一 数据库锁竞争与只读入口

沿 `cli.py`、`collect.py`、`store.py`、`lock.py`、`reports.py`、`handoff_view.py` 和日报入口找实际读写边界：

1. 用临时 home、临时 SQLite 库和合成个人 Git 仓复现并发场景。使用明确同步点控制两个实际连接或进程的顺序；保存谁持锁、另一方调用什么入口、退出码与实际结果。不能仅 monkeypatch 一个异常就宣称复现了真实锁竞争。
2. 核对现有只读查询是否触发初始化、schema 变更、写入观察或模型。需要区分初始化/迁移与查询时，实施兼容的最小拆分。SQLite 自身 WAL/SHM 协调文件和应用数据写入要分清。
3. 核对现有写入口的锁与事务范围。Git 进程、文件生成、模型和外部网络不得在长数据库写事务内等待；本轮不重写整个后台协调器。
4. 取得写锁失败时要有有界结果，不得无限重试。特别检查“记录锁失败”又走初始化/写库入口造成的递归或二次竞争。若需要本地失败事件暂存，采用有界、唯一事件 ID、原子写入和幂等导入；只在实际问题需要时实现。
5. 保存旧观察，不重写或丢弃历史。`A → B → A` 要保留 A 再次出现，再扫描相同 A 才幂等。失败不能污染最近成功观察或假装本次扫描成功。

如果基线已满足某项要求，给出现有实现和检查结果，直接复用，不为了产生改动重做。

## 二 拆分三个状态维度

当前程序已经有范围、覆盖、时间和来源检查。先复用这些事实，以最小、兼容的方式在相关输出中区分：

| 字段 | 候选取值 | 判断依据 |
| --- | --- | --- |
| `collection_coverage` | complete / partial / unknown | 实际采集是否失败、是否首次基线、是否存在观察空档 |
| `content_coverage` | full / bounded / unavailable | 代码证据完整、被截断还是不可读取 |
| `interpretation_state` | rule_only / model_validated / failed | 当前版本只有规则结果、模型结构与引用校验通过，还是解释失败 |

本轮不增加后台模型任务；如现有流程确有等待态，可以保留并明确说明，不能为了字段创建协调系统。`model_validated` 不代表解释语义已验收。缺少独立证据时使用 unknown/unavailable，不能从文件名、HEAD 变化、另一个工作树成功或旧报告借用结论。

这些维度是候选输出字段，不是先验存在的 API。先确定最小落点，保持旧 CLI 返回码和已有消费者兼容。用户可见文案用普通中文解释缺口。无需增加项目面板、目标录入或任务系统；确需 schema 增量时保留旧库兼容，不破坏既有观察和报告校验。

## 必须保留的行为

- 当前授权范围、停用/重新启用、符号链接与 Git 指针检查；未知项目不能因扫描或云端开发获得授权。
- 日报与交接各自的覆盖定义。补充工作树不能未经证据成为已登记交接范围。
- 旧报告保留，但陈旧、来源改变、最近失败或正文/依据不匹配时拒绝当作正常资料。
- 测试与部署状态只来自独立证据；不能因为修复完成或 unittest 通过就提升其它项目的测试/发布结论。
- 采集、只读查询、菜单读取不加载模型；失败保留清楚标记的规则结果。
- 否认公司路径与已撤销来源的保护规则，以及临时目录中的合成拒绝访问测试。不得打开真实公司目录来验证。

## 必要回归

根据实际改动覆盖正常路径与反例，避免仅复刻实现：

- 正常初始化、扫描、日报/交接生成和只读查询仍能完成。
- 实际锁竞争下查询和写入的返回行为明确、等待有界；锁释放后能够恢复，不重复观察或事件。
- 最近失败之后，旧报告不能变成当前成功；一棵树成功不能替另一棵失败树证明覆盖。
- 同一证据分别出现 complete/partial/unknown、full/bounded/unavailable 和 rule_only/failed 时，输出不混淆或升级结论。
- 只读入口不产生应用记录或 schema 写入，不启动模型、外部服务或业务仓命令。
- 既有 `A → B → A`、范围变更、未来时间、mtime 伪新鲜、正文哈希与观察 ID 检查保留。
